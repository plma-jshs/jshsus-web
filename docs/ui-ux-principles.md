# JSHSUS UI/UX 디자인 원칙

이 문서는 과구리(공개 서비스)와 관리자 포털을 함께 수정·검증할 때 지켜야 할 합의사항을 정리한 기준 문서다. 화면을 새로 설계할 때보다 기존 UI를 안전하게 개선할 때 우선 적용한다.

## 1. 제품 경계와 공통화

- 과구리는 학생·교직원이 빠르게 읽고 조작하는 모바일 중심 서비스이고, 관리자는 테이블·필터·작업을 많이 사용하는 업무 화면이다. 정보 밀도와 화면 구성은 제품별로 다르게 유지한다.
- 대신 저수준 동작과 시각 토큰은 공유한다. 검색 입력, 선택 박스, 세그먼트 탭, 페이지네이션 primitive, DialogShell, FilterSheet, 버튼 variant, loading/empty/error 상태를 먼저 공통 컴포넌트로 사용한다.
- 같은 의미의 요소를 페이지마다 임의로 복제하지 않는다. 공통 컴포넌트에 필요한 차이는 `className`, `variant`, 슬롯/콜백으로 표현하고, 컴포넌트 밖에서 같은 CSS를 재정의하지 않는다.
- 공개 페이지의 링크형 액션과 관리자 작업 버튼은 의미와 권한이 다르므로 컴포넌트는 분리할 수 있지만, 포커스·활성·비활성·터치 피드백 토큰은 동일하게 둔다.

## 2. 반응형 기준

- 검증 폭은 최소 800, 1023, 1024, 1440px에서 확인한다. 1024px 미만은 관리자 축소 레이아웃(사이드바 메뉴 버튼, 컴팩트 테이블, 2단 툴바)으로 본다.
- 검색창만 남는 폭을 유동적으로 줄인다. 나머지 필터·드롭다운·액션 버튼은 고정된 최소 폭과 간격을 유지한다.
- 1024px 미만 툴바는 1행에 전체 너비 검색창, 2행에 필터(좌측)와 액션(우측)을 둔다. 요소가 다음 줄로 어색하게 밀리거나 빈 필터 공간을 예약하지 않도록 `min-width: 0`과 명시적 grid를 사용한다.
- 휴대폰(<768px)은 테이블 대신 카드 또는 누적 더보기 목록을 사용한다. 태블릿(768–1023px)은 중요도가 낮은 컬럼을 숨긴 축소형 테이블을 사용한다.
- 모바일 하단 시트와 고정 푸터에는 `env(safe-area-inset-bottom)`을 반드시 반영한다. 데스크톱 전용 인쇄·대량 작업 버튼은 모바일에서 숨긴다.
- 공개 목록 툴바도 관리자와 같은 1024px 기준을 사용한다. 768–1023px에서는 검색창을 1행 전체로 두고, 2행의 필터와 작성/인쇄 같은 액션을 고유 너비로 오른쪽에 정렬한다. 필터가 없는 페이지는 빈 필터 열을 예약하지 않는다.
- 공개 모바일 탐구활동서처럼 날짜 범위를 제공하는 필터 시트에는 `오늘/7일/1개월/전체` 빠른 기간 칩을 둔다. 이 칩은 데스크톱 인라인 툴바나 일반 본문에 노출하지 않는다.
- 바텀시트의 동작은 저수준 `SheetFrame`에서 통합한다. `FilterSheet`(필터), `DialogShell`을 사용하는 `Dialog`/`Drawer`(상세·작성), 행 작업 메뉴는 모두 같은 드래그 핸들·스냅백·닫힘 흐름을 조합하고, 화면별 CSS는 폭·본문·푸터 배치만 소유한다. 새 시트를 추가할 때 직접 `useSheetDrag`나 핸들 마크업을 복제하지 않는다.

## 3. 검색·선택·탭

- 모든 검색창은 왼쪽 돋보기 아이콘, 오른쪽 값 지우기 X 버튼, 동일한 높이·radius·border를 사용한다. 내부 input에 별도의 배경/outline을 주어 이중 포커스가 생기지 않게 한다.
- 검색 placeholder는 `기준1, 기준2 검색` 문법으로 통일한다. 예를 들어 `학번, 이름, 사유, 처리자 검색`처럼 기준만 나열하고, 일반 입력 폼의 안내 문구(제목·내용 입력 등)는 검색 문법으로 바꾸지 않는다.
- hover와 focus-visible은 같은 1px 외곽 테두리를 공유한다. hover는 연한 그린으로 테두리 색만 바꾸고, focus-visible은 브랜드 그린 테두리와 아주 옅은 반투명 halo만 사용한다. 안쪽(inset) 링, 2px 단색선, 이중 테두리는 금지하며 버튼이 아닌 입력·드롭다운에만 적용한다.
- 네이티브 select가 노출되지 않도록 `SelectPrimitive`/관리자 select를 사용한다. 학년·반은 `1학년`, `1반`처럼 실제 사용 언어로 표시하고, 상태의 기본 문구는 `전체`로 통일한다.
- 탭은 선택되지 않은 텍스트를 낮은 대비로, hover를 약간 굵게, 선택 이동은 짧은 transition으로 표현한다. 모바일 필터 시트의 탭은 한 행 전체를 사용한다.

## 4. 하단 시트·모달

- 모든 모바일 시트는 공통 `useSheetDrag`/`FilterSheet`/`DialogShell` 동작을 사용한다. 상단 드래그 핸들, 실시간 translate, 짧은 이동은 원위치 snap-back, 충분한 이동은 현재 위치에서 exit 애니메이션을 보장한다.
- backdrop 클릭, X, Escape, 작업 완료 등 모든 닫힘 경로는 동일한 exit 애니메이션을 거친다. snap-back 직후 backdrop을 누르는 경우에도 `is-snapping`이 exit animation을 덮어쓰지 않아야 한다.
- 시트 헤더 제목 크기와 하단 여백을 통일하고, 헤더 아래 장식성 구분선은 사용하지 않는다. 긴 스크롤 모달에서만 sticky footer와 얇은 보더를 사용한다.
- 필터 시트에는 라벨→입력 간격과 입력 간 간격을 일정하게 적용한다. 탭은 1행, 날짜 범위는 `시작일 ~ 종료일` 한 행으로 둔다. 초기화는 왼쪽, 적용은 오른쪽(1:3)이며 기본 상태에서는 비활성/낮은 투명도로 표시한다.
- 핸들에서 제목까지는 충분한 상단 여백을 두고 제목 좌우 패딩을 통일한다. 제목과 첫 액션 사이 여백은 과도하게 벌리지 않으며, 액션 버튼 높이는 유지하고 버튼 사이 간격은 약 4px로 맞춘다. 초기화 텍스트는 아이콘이 있어도 한 줄을 유지한다.
- 행 작업 시트의 제목이 이미 대상을 명시하면 버튼은 `수정`, `삭제`, `이동`, `승인`처럼 짧은 동사만 표시한다. 전체 대상명은 `aria-label`과 데스크톱 보조 정보에만 남긴다.
- 모바일 터치 피드백은 일반 버튼의 `active` 배경 변화만 허용한다. 입력·드롭다운을 누른 뒤 포커스 배경이 남거나 sticky focus가 생기지 않도록 한다.
- 모바일 리스트 행과 카드에는 hover 상태를 만들지 않는다. 행을 누르는 짧은 순간에만 `--j-ref-slate-100` 수준의 아주 옅은 중립 음영을 적용하고, 입력·드롭다운·버튼에는 hover/focus 테두리를 남기지 않는다.
- 달력 날짜 셀도 같은 규칙을 따른다. 선택 상태와 누른 상태를 분리하고, 터치 후 첫 날짜나 이전 포커스 셀에 hover 음영이 남지 않도록 한다.

## 5. 목록·테이블·페이지네이션

- 데스크톱 페이지네이션은 공통 primitive를 사용하고, `page`/`size` URL과 실제 상태를 항상 동기화한다. 허용되지 않은 size는 20으로 정규화하고, 필터·검색·size 변경은 1페이지로 돌아간다.
- 모바일은 기본 20개를 보여주고, 중앙의 회색 `더보기` 버튼으로 20개씩 같은 화면에 append한다. 페이지 새로고침, URL 페이지 이동, `전체 n건 중 n-n` 요약은 모바일에서 표시하지 않는다. 더보기 중에는 버튼 안 스피너만 보여준다.
- 로딩 중 테이블 본문은 중앙에 스피너 하나만 표시한다. `불러오고 있습니다` 문구와 empty 아이콘은 사용하지 않는다. 빈 상태는 짧은 텍스트를 같은 중앙 위치에 표시한다.
- 요약 문구는 `전체 n건/명/개` 형식으로 통일하고, 아직 수를 모를 때는 0이나 skeleton 대신 가벼운 하이픈을 사용한다. 값이 없는 셀은 하이픈 대신 빈칸으로 둔다.
- 1–2명은 전체를 표시하고, 3명 이상은 대표 1명과 `외 n명`으로 줄인다. 팝오버는 1–4명 1열, 5명 이상 2열이며 학번은 고정폭·열 우선 순서로 정렬한다.

## 6. 상태·날짜·인쇄

- 상태는 대기/승인/반려의 텍스트와 낮은 대비의 배경을 사용한다. 불필요한 점·말줄임·두꺼운 테두리·강한 그림자를 추가하지 않는다.
- 관리자 날짜는 현재 연도면 연도를 생략하고, 다른 연도면 포함한다. 상벌점 기준일은 점(`.`) 표기를 사용한다.
- 탐구활동서 목록은 교시를 `1·2·3면학`처럼 묶어 표시하고 시각은 목록에서 숨긴다. 상세와 인쇄 미리보기/출력은 요구된 시간 표현을 일관되게 사용하며 미리보기와 실제 출력의 열 너비·여백이 같아야 한다.
- 달력의 이전/다음 달 날짜는 요일·공휴일 여부와 관계없이 낮은 대비의 회색으로 표시한다. 현재 달 공휴일만 낮은 대비의 rose-50 배경과 붉은 텍스트를 사용한다.
- 공개·관리자 달력은 공통 `CalendarGrid`를 사용하며 날짜 셀은 연한 쿨그레이(`#f3f6f8`)를 기본으로 한다. hover는 한 단계 어두운 쿨그레이, active는 짧은 slate 음영, 선택/focus는 셀 안쪽 1px 선으로 표시해 바깥 경계가 잘리지 않게 한다. 모바일은 주간 행 사이에 약 3px 간격을 둔다.

## 7. 접근성·모션·데이터 품질

- 키보드 focus-visible, Escape 닫기, 올바른 aria-label/role을 유지한다. `prefers-reduced-motion`에서는 시트·탭·달 전환을 즉시 처리한다.
- 이미지에는 지연 로딩과 실패 대체 처리를 적용한다. 장식 이미지는 빈 alt, 정보 이미지는 의미 있는 alt를 둔다.
- React SPA 라우트 진입 시 GA4 `page_view`를 수동 기록한다(`page_title`, `page_location`, `page_path`). 한 페이지에 Google 태그를 중복 삽입하지 않는다.
- 리치 텍스트 툴바는 편집기 폭을 넘지 않는다. 고정된 도구 그룹은 한 줄로 유지하고 폭이 부족하면 툴바 자체가 가로 스크롤하며, 드롭다운/팔레트는 포털 메뉴로 열어 잘리지 않게 한다. 툴바의 모든 트리거도 입력과 같은 단일 1px 테두리·부드러운 focus halo 정책을 따르고, 모바일 터치에서는 sticky 링 없이 순간적인 중립 pressed 배경만 허용한다.
- 모든 앱의 입력·선택·검색·페이지 입력은 공통 `control-policy.css`의 1px 테두리와 동일한 radius를 사용한다. 이중 wrapper/input 테두리, 2px 단색 테두리, inset 링, 진한 외곽 그림자, 브라우저 기본 파란 active 배경은 금지한다. 데스크톱은 hover(연한 그린으로 테두리 색만 변경)와 `:focus-visible`(브랜드 그린 1px 테두리 + 옅은 halo)만 허용하고, 모바일은 입력·선택의 hover/focus 변화를 제거한다. 버튼은 키보드 `focus-visible`만 남기며 터치 순간의 중립 회색 active 표면만 허용한다.
- `html`에는 `scrollbar-gutter: stable`을 적용해 세로 스크롤이 생길 때 본문이 좌우로 움찔하지 않도록 한다. 페이지별로 별도 scrollbar 보정 여백을 추가하지 않는다.
- 모바일 리스트 행에는 hover 스타일을 만들지 않는다. 탭·필터·버튼의 터치 피드백은 손가락을 누르는 동안만 보이고, 손가락을 뗀 뒤 상태가 남지 않아야 한다.
- Google 태그는 빌드 시 `<head>`에 한 번만 삽입한다. SPA 라우트 진입 시 공개 페이지에서만 수동 `page_view`를 기록하며, `page_title`, `page_location`, `page_path`를 함께 보낸다.
- hover/focus를 전역에서 무조건 삭제하지 않는다. 마우스 hover는 입력·선택 primitive에서만 1px 테두리 색상 변화로 제공하고, 키보드 사용자는 `:focus-visible` 1px 테두리와 옅은 halo로 항상 위치를 확인할 수 있어야 한다. 모바일 터치에는 focus ring을 남기지 않고 `:active`의 짧은 중립 표면만 허용한다.
- 바텀시트/모달은 공통 shell이 드래그 핸들, safe-area, 제목·첫 항목 간격, footer 버튼 높이, drag snap-back/close 애니메이션을 소유한다. 시트를 닫는 순간 내부 콘텐츠와 흰색 surface가 같은 transform을 사용해야 하며, 닫힘 이벤트에서 즉시 unmount하지 않는다.

## 8. 기능별 추가 규칙

- 휴대폰 보관함은 `보관함 관리`와 `cron 스케줄 관리` 탭을 제공한다. 스케줄은 보관함·잠금 상태·실행 시각을 저장하고 API worker가 주기적으로 due 작업을 실행한다. 실행 완료 작업은 목록에서 제거하고 명령 기록과 감사 로그를 남긴다.
- 기상곡 신청은 다음 주 월요일부터 일요일까지를 후보 주차로 사용한다. YouTube 미리보기는 자막을 기본 해제하고, 읽기 전용 관리자 미리보기에서는 네이티브 컨트롤을 숨긴다. 서버에는 YouTube URL/구간만 저장하므로 오디오 바이너리를 MP3로 가장해 내려받지 않는다.
- 청원 목록은 본문 미리보기를 노출하지 않고 `MM.DD · D-n` 형식의 날짜/마감 배지를 사용한다. 참여 CTA는 옅은 회색 박스에 두고, 참여 완료 상태는 체크 아이콘과 비활성 버튼으로 표시한다. 작성·수정 화면은 번호 매긴 섹션과 장식 구분선을 제거하고 일반 폼의 라벨·입력 순서를 따른다.
- 폰트·색상 리치 텍스트 드롭다운은 포털에서 고정 폭으로 렌더링하고 viewport를 넘지 않게 한다. 팔레트의 hex 입력과 적용 버튼은 툴바 높이를 넘지 않는다.
- 기상곡 관리자에서 YouTube 원본은 외부 스트림이므로 MP3 바이너리를 생성·위조하지 않는다. 저장된 URL·구간·배속을 편집하고, 다운로드는 편집 정보 manifest로 명확히 표시한다. 실제 MP3가 필요하면 별도 음원 업로드/저작권 검토와 서버 인코딩 저장소를 먼저 설계한다.
- 공통 primitive를 도입하더라도 제품별 정보 밀도와 동작은 유지한다. 차이가 필요한 경우 새 CSS 복제 대신 primitive의 variant/slot/className으로 표현한다.
